# FlightHub Frontend

A clean and modern Express.js-based frontend for the FlightHub flight booking system.

## Setup Instructions

### Prerequisites
- Node.js 14+ installed
- FastAPI backend running on `http://localhost:8000`

### Installation

1. Navigate to the frontend directory:
```bash
cd frontend
```

2. Install dependencies:
```bash
npm install
```

3. Start the server:
```bash
npm start
```

The frontend will be available at `http://localhost:3000`

## Features Implemented

### ✅ 1. Flight Listings (index.html)
- **Status**: Fully Implemented
- **Features**:
  - Displays all available flights from the backend
  - Shows: origin, destination, departure date/time, duration, price, available seats
  - Flight cards with attractive UI using gradient headers
  - "Book Now" button for available flights (seats_available > 0)
  - "Sold Out" message for fully booked flights
  - Error handling with user-friendly messages
  - Empty state message when no flights exist

### ✅ 2. Flight Search (search.html)
- **Status**: Fully Implemented
- **Features**:
  - Filter by origin (case-insensitive, partial match)
  - Filter by destination (case-insensitive, partial match)
  - Filter by departure date (YYYY-MM-DD format)
  - At least one search parameter is required (validated on frontend)
  - Returns matching results or "No flights found" message
  - Displays same flight card format as listings for consistency
  - Form validation ensures at least one field is filled

### ✅ 3. Book a Flight (book.html)
- **Status**: Fully Implemented
- **Features**:
  - Flight summary displayed on the page
  - Input fields for:
    - Passenger full name (min 2 characters)
    - Passport number (5-50 characters)
    - Seat number (max 10 characters, free text format like "12A")
  - Form validation with HTML5 constraints
  - Unique booking reference auto-generated by backend (FH-XXXXXX format)
  - Success message with booking reference displayed
  - Automatic redirect to bookings page after successful booking
  - Error handling for seat unavailability, flight not found, etc.

### ✅ 4. View Bookings (bookings.html)
- **Status**: Fully Implemented
- **Features**:
  - Search by passenger name (case-insensitive partial match)
  - Search by booking reference (exact match)
  - At least one search parameter required
  - Displays comprehensive booking information:
    - Booking reference
    - Flight details (number, route, departure time, duration, price)
    - Passenger details (name, passport, seat, booking date)
    - Booking status (confirmed/cancelled with icon)
  - Status-based styling (green for confirmed, red for cancelled)
  - Booking cards with nice layout showing all nested flight info

### ✅ 5. Cancel a Booking (bookings.html)
- **Status**: Fully Implemented
- **Features**:
  - Cancel button visible only for confirmed bookings
  - Confirmation dialog before cancellation
  - Updates seat availability on the flight (backend handles increment)
  - Success message showing cancellation confirmation
  - Booking status updates from "confirmed" to "cancelled"
  - Cancelled bookings show status indicator without cancel option
  - Error handling for already cancelled bookings

## API Routes

The Express server proxies requests to the FastAPI backend:

- `GET /api/flights` → `GET http://localhost:8000/flights`
- `GET /api/flights/search?origin=...&destination=...&date=...` → Backend search
- `POST /api/bookings` → Create booking
- `GET /api/bookings?name=...&ref=...` → Search bookings
- `DELETE /api/bookings/{reference}` → Cancel booking

All business logic validation is handled by the backend, and the frontend properly displays backend error messages.

## Error Handling

The frontend gracefully handles all backend errors:

- **400 Bad Request**: Missing search parameters
- **404 Not Found**: Flight/Booking not found
- **409 Conflict**: No seats available, seat already taken, booking already cancelled
- **500 Server Error**: Network issues or backend problems

Error messages are displayed to users in a user-friendly format.

## Testing the Application

1. **Start backend**: `uvicorn backend.main:app --reload --port 8000`
2. **Seed flights**: `python -m backend.seed`
3. **Start frontend**: `npm start` (in frontend directory)
4. **Open browser**: `http://localhost:3000`
5. **Test workflow**:
   - View all flights on homepage
   - Search for specific flights
   - Book a flight with test passenger data
   - View bookings using passenger name or reference
   - Cancel a booking
